## Purpose

- describe what each item means and what operators should do when it appears
- keep this file aligned with endpoint responses and run-export diagnostics

## Error Catalog

All errors below are returned as machine-readable identifiers in the
`X-NIPE-Error-Type` HTTP header (or equivalent payload field).

### `unsupported_format`
- Domain: ingestion
- Trigger: uploaded content does not match supported ingestion input types
- Typical fix:
  - re-upload one of the supported file formats
  - preserve plain-text chapters when using directory uploads
  - retry after validating the input source

### `unsupported_encoding`
- Domain: ingestion
- Trigger: corpus bytes decode path cannot be interpreted with supported encodings
- Typical fix:
  - normalize the source file to UTF-8 encoding before upload
  - avoid mixed or damaged encoding in source text
  - retry with a cleaned export from the original source

### `missing_chapters`
- Domain: ingestion
- Trigger: upload succeeded technically but no usable chapter payload was produced
- Typical fix:
  - verify the file is non-empty and contains readable chapter content
  - for chapter-directory uploads, ensure filenames and chapter boundaries are valid
  - retry after re-validating source text and separators

## Warning Catalog

Warning payloads are typically surfaced in:
- ingestion logs (`ingestion_log.warnings`)
- run logs/exports (`manifest.logs.*`)
- config telemetry for provider fallback (`runs.config_json.deterministic_warnings`)

### `ambiguous_chapter_boundaries`
- Domain: ingestion/normalization
- Meaning: chapter boundary heuristics matched multiple marker patterns and fallback splitting was used
- Remediation:
  - standardize chapter markers (`Chapter 1`, `##`, etc.) before retry
  - avoid ambiguous or mixed heading styles in the same file
  - if boundary intent is correct, continue; warnings are informational

### `quote_repair_confidence_low`
- Domain: normalization
- Meaning: quote-style repair ran with low-confidence matches
- Remediation:
  - review output around repaired segments
  - keep canonical punctuation style consistent in source text
  - use manual QA if repaired passages become semantically wrong

### `suspected_duplicate_content`
- Domain: ingestion/normalization
- Meaning: two chapters show high textual similarity above duplicate threshold
- Remediation:
  - inspect duplicate chapter pair IDs in warning payload
  - remove one duplicate source or split intentionally duplicated content
  - re-run ingestion after source cleanup

### `duplicate_chapter_title`
- Domain: ingestion
- Meaning: normalized chapter titles collide across multiple chapter rows
- Remediation:
  - rename or namespace duplicate titles before ingestion
  - avoid using the exact same title string for repeated sections
  - accept auto-handling when duplicates are intentional

### `chapter_title_dedup_action`
- Domain: ingestion
- Meaning: duplicate-title cleanup helper payload generated by normalization
- Remediation:
  - use the emitted `dedup_keys` when harmonizing chapter references
  - keep the canonical chapter occurrence and update downstream references if needed
  - re-run ingestion only if source titles were corrected

### `ambiguous_replacement`
- Domain: pronunciation replacement preview
- Meaning: a term resolves to conflicting verbalized forms across scopes (e.g., global vs character/place scope)
- Remediation:
  - review and collapse conflicting dictionary rows
  - restrict preview scope to one intended precedence order
  - update pronunciations to a single unambiguous replacement per term

### `ambiguous_alias_collision`
- Domain: character canonicalization
- Meaning: the same alias maps to multiple canonical character names
- Remediation:
  - choose one canonical target per alias
  - move the remaining alias variants into disambiguating names
  - rerun extraction/mapping after alias cleanup

### `duplicate_canonical_candidates`
- Domain: character extraction
- Meaning: extracted candidate name repeats with normalization collisions
- Remediation:
  - normalize aliases upstream and remove duplicate rows
  - keep one canonical spelling per entity
  - re-run character extraction if duplicates are fixed

### `low_confidence_character_candidate`
- Domain: character extraction
- Meaning: extracted character candidate confidence is below threshold
- Remediation:
  - review candidate against context and promote only valid characters
  - add manual canonical corrections where needed
  - allow unresolved candidates to pass when confidence improves in later passes

### `manual_inferred_gender_contradiction`
- Domain: character gender analysis
- Meaning: manually set gender disagrees with inferred gender
- Remediation:
  - resolve intentionally against manual truth and keep one source-of-truth policy
- If contradiction is intentional, add reviewer notes and keep the manual setting

### `inferred_gender_insufficient_evidence`
- Domain: character gender analysis
- Meaning: inferred gender confidence does not exceed minimum evidence threshold
- Remediation:
  - add stronger manual character context in map
  - keep inference field as provisional until manual review
  - re-run inference after map adjustments

### `low_confidence_speaker_attribution`
- Domain: tagging
- Meaning: segment speaker assignment confidence is low or uncertain
- Remediation:
  - inspect ambiguous dialogue segments and fix speaker attributions in map/voice metadata
  - split or normalize complex dialogue formatting in source text
  - rerun run generation for updated speaker evidence

### `high_ambiguity_dialogue_block`
- Domain: tagging
- Meaning: a dialogue/mixed block carries many competing ambiguity flags
- Remediation:
  - prioritize explicit markup in source (`"`/speaker cues)
- verify whether the segment is truly ambiguous by design or should be manually reviewed

### `unstable_rapid_emotion_shift`
- Domain: tagging/emotion
- Meaning: dense emotion transitions in a short segment indicate tonal instability
- Remediation:
  - inspect original segment for inconsistent emotional markup or OCR noise
  - leave warning as analytical signal for review if narrative intentionally shifts rapidly

### `deterministic_replay_warning`
- Domain: pipeline provider execution
- Meaning: deterministic mode requested one provider but runtime used a different one (provider fallback after retries)
- Remediation:
  - confirm provider quotas and health before replaying runs
  - pin available fallback policy explicitly for strict deterministic workflows
  - compare exported snapshots to ensure acceptable drift before release

## Operational note

- `ambiguous_alias_collision`, `high_ambiguity_dialogue_block`, `unstable_rapid_emotion_shift`,
  `low_confidence_speaker_attribution`, `suspected_duplicate_content`, and
  `quote_repair_confidence_low` are high-signal items and should be surfaced in review QA before publish workflows.
